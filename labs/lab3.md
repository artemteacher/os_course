# Лабораторная работа 3. Виртуальная память. Срок сдачи до 26 ноября

## Тема: виртуальная память своими глазами — два коротких опыта

## Цель работы

Увидеть на практике, как ОС на самом деле выделяет память программе и как устройство памяти (страницы, TLB, кэш процессора) влияет на скорость программы.

---

## 1. Как устроена работа

Работа состоит из двух небольших опытов. Каждый опыт — это короткая программа (обычно 20–40 строк) и несколько вопросов, на которые нужно ответить по результатам в отчете (!!!).

**Язык программирования — любой.** В приложении А есть подсказки для C, C++, Rust, Go, Python, Java, C# и JavaScript (Node.js). Если вы пишете на другом языке, найдите в нём аналоги.

Если ваш язык ведёт себя не так, как описано в задании, — это не ошибка, а результат: запишите его и попробуйте объяснить.

**Прежде чем запускать** каждый опыт, запишите в отчёт короткий прогноз: что, по-вашему, получится. За неверный прогноз оценка не снижается — важно потом честно сравнить прогноз с результатом.

## 2. Подготовка

1. **Нужен Linux.** Подойдёт любой вариант:
   - Linux, установленный на компьютере;
   - Windows: WSL2. Работайте в домашней папке Linux (`cd ~`), а не в папках `/mnt/c/...`;
   - macOS или Windows без WSL2: виртуальная машина с Linux (VirtualBox, UTM и т. п.).
2. **Нужно около 2 ГБ свободной оперативной памяти** (посмотреть: `free -h`, столбец `available`). Если памяти меньше, в опыте 1 используйте блок 256 МБ вместо 1 ГБ, а в опыте 2 — N = 4096 вместо 8192.
3. **Компилируемые языки собирайте с оптимизацией**: `gcc -O2`, `cargo build --release` и т. п.

## 3. Общие инструменты

Всё нужное о памяти своего процесса программа может узнать, прочитав два текстовых файла. Это работает в любом языке, где можно прочитать файл.

**Сколько памяти процесс реально занимает (RSS).** В файле `/proc/self/status` найдите строку, которая начинается с `VmRSS:`. Число в ней — объём в килобайтах.

```
VmRSS:      9876 kB
```

**Сколько было страничных прерываний (page fault).** Файл `/proc/self/stat` — одна строка с полями через пробел. Достать из неё нужное число можно так:

```
текст = прочитать файл "/proc/self/stat"
хвост = часть текста после ПОСЛЕДНЕЙ закрывающей скобки ")"
поля  = хвост, разбитый по пробелам
minor = поля[7]     (нумерация с нуля)
```

Число растёт с момента запуска процесса. Чтобы узнать, сколько прерываний произошло за какой-то этап, вычтите значение до этапа из значения после.

**Совет.** Напишите функцию, которая печатает RSS (в мегабайтах) и число minor fault'ов с подписью этапа, например `print_mem("после выделения")`, и вызывайте её в нужных местах.

**Время.** Измеряйте монотонными часами своего языка (см. приложение А): разница двух замеров — это прошедшее время в миллисекундах.

**Размер страницы.** Обычно 4096 байт (4 КБ). Узнать точно: команда `getconf PAGESIZE` или функция вашего языка (приложение А).

**Ловушка оптимизатора.** Компилятор или JIT может выбросить действия, результат которых нигде не используется: запись в память, которую никто не читает, или сумму, которую никто не печатает. Поэтому в конце каждого опыта обязательно используйте результат: напечатайте сумму или какой-нибудь байт из массива.

## 4. Задания: нужно провести два опыта

### Опыт 1. «Выделить — не значит получить»

1. Напечатайте RSS и число minor fault'ов в начале программы.
2. Выделите блок памяти размером 1 ГБ (1 073 741 824 байта), **ничего в него не записывая**. Напечатайте RSS и minor.
3. Запишите **по одному байту в каждую страницу** блока и измерьте время:
   ```
   для i от 0 до размера_блока с шагом размер_страницы:
       блок[i] = 1
   ```
   Напечатайте время, RSS и minor.
4. Повторите ту же запись (`блок[i] = 2`) и снова напечатайте время, RSS и minor.
5. В конце напечатайте какой-нибудь байт блока, например `блок[12345]`.

Результаты сведите в таблицу:

**Если RSS вырос сразу после выделения**, значит, ваш язык или его среда выполнения сами заполняют новую память нулями. Так ведут себя `new byte[]` в Java, `std::vector` в C++, `bytearray` в Python. ## 5. Если что-то пошло не так

| Что вы видите | Вероятная причина | Что сделать |
|---|---|---|
| Опыт 1: RSS вырос сразу после выделения | Язык сам заполняет новую память нулями | Это результат — запишите его; затем используйте способ без заполнения из приложения А |
| Опыт 1: время записи около нуля, minor не растут | Компилятор выбросил запись, потому что результат не используется | Напечатайте байт блока в конце (шаг 5 опыта 1) |
| Опыт 1: minor fault'ов в сотни раз меньше, чем страниц | Включены большие страницы (Transparent Huge Pages): одно прерывание сразу выделяет 2 МБ | Это нормально. Проверьте `cat /sys/kernel/mm/transparent_hugepage/enabled` и объясните результат в отчёте |
| Опыт 2: разница между обходами маленькая | Программа собрана без оптимизации, или в Python используются обычные списки | Соберите с `-O2` / `--release`; в Python используйте numpy |
| Компьютер стал сильно тормозить, процесс завершился со словом `Killed` | Не хватило оперативной памяти | Уменьшите размер блока (опыт 1) или N (опыт 2) |

## Приложение А. Подсказки по языкам

Во всех языках RSS и число page fault'ов берутся из файлов `/proc/self/status` и `/proc/self/stat` (раздел 3) — нужно только уметь читать текстовый файл.

### C / C++
- **Время:** `clock_gettime(CLOCK_MONOTONIC, &ts)`; в C++ — `std::chrono::steady_clock::now()`.
- **Размер страницы:** `sysconf(_SC_PAGESIZE)`.
- **1 ГБ без заполнения:** `malloc(1L << 30)`; в C++ — `new char[1L << 30]`. `std::vector<char>(n)` заполняет память нулями.
- **Сборка:** `gcc -O2 -o prog prog.c`.

### Python
- **Время:** `time.perf_counter()` (в секундах).
- **Размер страницы:** `mmap.PAGESIZE`.
- **1 ГБ без заполнения:** `mmap.mmap(-1, 1 << 30)` — анонимное отображение. `bytearray(1 << 30)` заполняет память нулями.
- **Опыт 2:** numpy (`pip install numpy`): `a = np.arange(N*N, dtype=np.int32).reshape(N, N)`. По строкам — цикл по `i` с суммой `a[i, :].sum()`, по столбцам — цикл по `j` с суммой `a[:, j].sum()`. Сумму среза считает numpy, поэтому цикл на Python здесь всего N итераций.

### Go
- **Время:** `start := time.Now()`, затем `time.Since(start)`.
- **Размер страницы:** `os.Getpagesize()`.
- **1 ГБ без заполнения:** `make([]byte, 1<<30)` — Go получает от ОС уже обнулённую память и сам её не заполняет.

### Rust
- **Время:** `let t = std::time::Instant::now();`, затем `t.elapsed()`.
- **Размер страницы:** 4096 или `libc::sysconf(libc::_SC_PAGESIZE)` (пакет `libc`).
- **1 ГБ без заполнения:** `vec![0u8; 1 << 30]` — такой вектор выделяется через `calloc` и заранее не заполняется.
- **Защита от оптимизатора:** `std::hint::black_box(значение)`.
- **Сборка:** `cargo build --release`.

### Java
- **Время:** `System.nanoTime()` (в наносекундах).
- **1 ГБ:** `new byte[1 << 30]` (запуск с `java -Xmx2g ...`) — JVM сама заполняет массив нулями, поэтому RSS вырастет сразу. Запишите это, затем повторите опыт со способом без заполнения — частным отображением пустого («разреженного») файла:
  ```java
  RandomAccessFile raf = new RandomAccessFile("big.bin", "rw");
  raf.setLength(1L << 30);                       // файл 1 ГБ, место на диске не занимает
  MappedByteBuffer m = raf.getChannel().map(FileChannel.MapMode.PRIVATE, 0, 1L << 30);
  m.put(i, (byte) 1);                            // запись байта по индексу i
  ```
  В конце удалите файл `big.bin`.
- **Опыт 2:** `int[] a = new int[N * N]`, запуск с `java -Xmx1g ...`.

### C#
- **Время:** `var sw = System.Diagnostics.Stopwatch.StartNew();`, затем `sw.Elapsed.TotalMilliseconds`.
- **1 ГБ без заполнения:** `byte* p = (byte*)NativeMemory.Alloc(1 << 30);` (пространство имён `System.Runtime.InteropServices`, .NET 6 и новее). Нужен небезопасный код: в файле проекта `<AllowUnsafeBlocks>true</AllowUnsafeBlocks>`. Для сравнения проверьте, что происходит с RSS при `new byte[1 << 30]`.

### JavaScript (Node.js)
- **Время:** `performance.now()` (в миллисекундах).
- **1 ГБ без заполнения:** `new Uint8Array(1 << 30)` — память заранее не заполняется.
- **Опыт 2:** `new Int32Array(N * N)`.
