# Лабораторная работа 1. Скрипт сбора диагностики для технической поддержки. Срок сдачи до 1 октября

## 1. Легенда

Вы работаете в технической поддержке. Клиент пишет: «сервер стал тормозить, всё зависает». Удалённого доступа к машине нет, клиент — не администратор и выполнять команды по инструкции не будет.

Стандартное решение: клиенту отправляют один скрипт и просят прислать результат его работы. Такие скрипты есть почти у каждого производителя серверного софта (`sosreport` в Red Hat, `supportconfig` в SUSE). Ваша задача — написать упрощённый вариант такого скрипта.

## 2. Постановка задачи

Скрипт `collect-info.sh` собирает диагностику в **один текстовый файл**:

```
sysinfo-<hostname>-<ГГГГ-ММ-ДД-ЧЧММ>.txt
```

Файл разделён на озаглавленные блоки. Последняя строка вывода скрипта — путь к этому файлу.

Архивы, временные каталоги и упаковка не нужны: один файл клиенту приложить проще, а вам — на 20 строк меньше кода.

## 3. Что собирать

Клиент жалуется на медленную работу, значит собираем то, что относится к производительности. Не «всё о компьютере», а то, что поможет найти причину.

| Блок | Команды | Что ищет инженер поддержки |
|---|---|---|
| Система | `uname -a`, `uptime`, `/etc/os-release`, `lscpu` | с чем имеем дело, сколько ядер |
| Нагрузка | `vmstat 1 5`, топ-10 процессов по CPU и по памяти | кто съел ресурсы и во что упирается машина |
| Диски | `df -h`, `df -i` | переполненный раздел или кончившиеся inode — самая частая причина «всё зависло» |

Два момента, которые здесь важнее остальных:

**`vmstat 1 5` — это серия, а не снимок.** «Тормозит» — состояние во времени. Одно значение не отличает ровно загруженную машину от той, что раз в минуту встаёт колом.

**Столбец `wa` в выводе `vmstat` — доля времени, когда процессор простаивал в ожидании диска.** Загрузка CPU 5 % при полностью неотзывчивой системе — обычное дело: процессы заблокированы на вводе-выводе. Без этого столбца отличить «не хватает процессора» от «не справляется диск» по отчёту невозможно.

## 4. Обязательные требования

1. **Таймаут.** Каждая команда вызывается через `timeout`. Если команда зависла, скрипт продолжает работу, а в файле остаётся пометка именно о таймауте (`timeout` возвращает код 124), отличная от пометки об ошибке.
2. **Проверка наличия.** Перед вызовом утилиты проверяется `command -v`. Отсутствие утилиты — не ошибка, а строка «команда недоступна».
3. **Работа без root.** Недоступные обычному пользователю данные помечаются, а не приводят к сообщениям об ошибках.
4. **Разделение потоков.** В stdout уходит только путь к файлу, прогресс («Собираю сведения о дисках...») — в stderr, вывод собираемых команд — в файл. Проверка: `./collect-info.sh 2>/dev/null` печатает ровно одну строку.
5. `shellcheck` без замечаний уровня error и warning.

Функции `run` и `say` из каркаса выполняют требования 1, 2 и 4 за вас — их достаточно правильно использовать.

## 5. Что сдаётся

Отчет со скриптом и результатом его работы. Будьте готовы, что при сдаче работы вам нужно будет запустить скрипт на вашей машине.

## Каркас для старта

```bash
#!/usr/bin/env bash
# collect-info.sh — сбор диагностики для технической поддержки

set -uo pipefail

OUT="sysinfo-$(hostname)-$(date +%F-%H%M).txt"
: >"$OUT"   # создать пустой файл отчёта

# Прогресс для клиента: только на экран (stderr), в файл не попадает.
say() { printf '%s\n' "$*" >&2; }

# Выполнить команду с таймаутом и записать вывод в отчёт.
# Использование: run "Заголовок" секунды 'команда с аргументами'
run() {
    local title=$1 tmo=$2 cmd=$3 rc
    printf '\n===== %s =====\n' "$title" >>"$OUT"

    if ! command -v "${cmd%% *}" >/dev/null 2>&1; then
        printf '(команда %s недоступна)\n' "${cmd%% *}" >>"$OUT"
        return 0
    fi

    timeout "$tmo" bash -c "$cmd" >>"$OUT" 2>&1
    rc=$?
    if [ "$rc" -eq 124 ]; then
        printf '(команда не уложилась в %s с — таймаут)\n' "$tmo" >>"$OUT"
    elif [ "$rc" -ne 0 ]; then
        printf '(команда завершилась с кодом %s)\n' "$rc" >>"$OUT"
    fi
    return 0
}

main() {
    say "Собираю общие сведения..."
    run "Система"   5 'uname -a'
    run "Аптайм"    5 'uptime'
    # TODO: /etc/os-release, lscpu

    say "Снимаю замеры нагрузки..."
    run "Нагрузка за 5 секунд" 10 'vmstat 1 5'
    run "Топ по памяти" 5 'ps -eo pid,user,%mem,%cpu,comm --sort=-%mem | head -11'
    # TODO: топ по CPU

    # TODO: блок про диски (say + df -h + df -i)

    printf '%s\n' "$PWD/$OUT"
}

main "$@"
```
